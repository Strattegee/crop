Path to go-live

Go-live is set by the calendar, not the build: everything before Christmas has about three weeks of slack, so nothing before then is on the critical path. The penetration test should now be booked for late November or early December rather than over Christmas. The lawyer's review needs the company details from the list first.

How the six streams run

  • Each stream is its own Claude Code cloud session on its own branch, working from the shared docs and CLAUDE.md.
  • Streams only touch their own module folders. Shared parts (schema, permissions) change only in Stream 1.
  • Each finished ticket arrives as a pull request with tests passing. You try it on staging and merge.
  • December is spare: Release 2 (timesheets, pay, invoice export) is built then, and C4U trials Release 1 on staging with invented people.

What keeps 11 January safe

  1. Send the items on "CROP: what we need from you" within two weeks (by 13 November).
  2. Book the penetration tester for 25 November to 4 December.
  3. Create the Expo account and finish the Apple and Google accounts, so the app goes to the stores in late November, before reviews slow down for Christmas.
  4. Send the legal drafts to the lawyer by mid-November.
  5. If the UI designer's screens run late, go live on the current layout with the new logo and colours, and roll out the full look afterwards.

Assumptions. Durations are working days and include your review time. Victorian public holidays are excluded. C4U's go-live preparation starts on Monday 4 January; nothing new reaches C4U between Christmas and New Year. The payroll specialist, penetration tester and the lawyer drafting terms are assumed available when needed. The revised dates use the first week's real build speed.
